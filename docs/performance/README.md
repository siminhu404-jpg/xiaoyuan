# 首屏模型优化

2026-11-20：入口所用的五个 GLB 合计约 3.83 MiB → 1.71 MiB，三角形约 54.9 万 → 14.0 万。

- 院门左右扇、房屋：目标保留 20% 几何，误差上限为模型半径的 0.1%。
- 枣树：目标保留 30% 几何，使用同样的误差上限。
- 人物不进行减面；2048 × 2048 贴图缩至 1024 × 1024，保留五套动画、骨骼和蒙皮。
- 纹理使用 JPEG quality 82，继续使用现有 Draco 解码器。
- 优化资源 URL 带版本参数，避免旧缓存遮蔽更新。

使用 Node.js >= 20.9，安装依赖后运行 `npm run optimize:entry`。脚本固定从提交 `34001a471cd00f6b1e2b7de6158a5acb256e7a46` 读取原始模型，避免重复压缩带来的累积损失。运行前需要 Git 中存在该提交（浅克隆需先获取历史）。原始模型可从该提交恢复。

每个文件的字节数、三角形、纹理尺寸及动画列表记录在 `entry-assets.json`。脚本写出前会重新解码压缩数据并核对动画名称。

验证：生产构建、78 项单元测试、3 项加载/失败重试/开门行走浏览器测试通过；对比了减面前后入口与前院截图，未发现正常游玩视角下明显的轮廓损坏。贴图压缩和减面有损，近距离细节不保证完全一致。

## 完整行走加载（2026-11-20）

所有区域立即挂载轻量几何外形，使用从模型提取的尺寸适配实际摆放。精细资产独立 Suspense；加载失败保留该物件的外形和热点，且释放队列名额。内院门/葡萄架的占位保留中间开口。

入口人物与外门准备好后自动启动后台队列，每次两个不同模型；顺序优先内院门、葡萄架、后院房屋，再家具、植物和猫。多个植物实例共用一次资源请求。取消“走近边界才挂载整组”的限制。

20 个廊亭/后院模型执行了带误差上限的减面与纹理缩小，记录见 `walk-assets.json`。可通过 Node >=20.9 运行 `node scripts/optimize-walk-assets.mjs` 重建；原始模型仍来自固定 Git 提交。占位尺寸可用 `node scripts/generate-asset-bounds.mjs` 重新生成。

这不保证精细模型在任意网络环境下即时出现；慢网时显示简化版本，失败时也保留简化版本，重新加载页面可重试。

验收：80 项单元测试；5 项浏览器测试，包括必要资源失败、慢请求时两个模型的并发限制、开门行走、模型失败时从前院经廊亭到后院并返回。完整路线用 Chromium Metal 后端测试；默认软件 GPU 在该场景的持续行走测试中帧率较低，未据此声称手机帧率达标。另检查了正常完整画面与慢网/失败时的占位画面。
