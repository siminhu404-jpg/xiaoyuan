# 《姥姥家的小院》设计文档

日期：2026-10-21
状态：已与用户确认（brainstorming 产出）

## 一句话

夏天午后，把姥爷姥姥老家的小院子装进手机里——一个「小时候的你」走在里面，走到哪儿，哪儿就活过来：葡萄藤晃、猫翻身、老照片浮出、一段回忆慢慢讲。

## 定位与目标用户

- **性质**：送给家人的礼物，成功标准是「他们能认出这里」
- **用户**：长辈为主（手机、微信内打开、零游戏经验），家人传播
- **平台**：移动优先（微信内置浏览器必须可用），桌面顺带支持

## 核心决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 技术路线 | React Three Fiber（Vite + React 18 + TS） | 复用用户 React 经验；照片/文字 UI 层是 React 主场；移动端包体可控 |
| 美术风格 | 低多边形绘本风 | 实现成本低、无恐怖谷、Tripo 生成资产适配 |
| 时刻定格 | 夏天午后 | 经典「回不去的夏天」意象 |
| 交互循环 | 自由探索 + 点击寻路 | 单指零门槛；有人物有行走有跟随镜头 |
| 人物方案 | 「小时候的你」小人，点击寻路 | 长辈会用（指挥而非操控）；电影感跟随 |
| 活物 | 猫群（3只性格各异）+ 蝴蝶，人物只出现在老照片 | 避免人物模型不像反而出戏 |
| 内容 | 动效 + 老照片 + 回忆文字（无音频） | 用户素材优势；文字必须用户本人写，AI 只润色 |
| MVP 范围 | 后院+廊亭+前院全场景，11 个 hotspot | 小而美，先跑通全链路 |

## 场景布局（依据用户口述）

```
                    北
┌────────────────────────────────────────┐
│  后院 · 老宅核心区（北方砖瓦房）            │
│   [月季]     堂屋·老宅正门      [月季]     │
│            [压水井]                      │
├────── 廊亭（原老院门，有顶）──────────────┤
│   围墙（墙头仙人掌🌵）                      │
│   🐱🐱🐱 猫群  🍇葡萄藤(靠墙)  🥬菜地      │
├────────────────────────────────────────┤
│   前院 · 新自建房区                        │
│   [新房·门口有枣树🍎]         [新房]       │
└───────────────[新大门]───────────────────┘
                    南 · 进门方向
```

- **「越走越旧」的纵深**：新大门 → 新自建房 → 廊亭（旧门）→ 老宅砖瓦房，建筑材质随脚步回退时间
- **廊亭是情感锚点**：原老宅院门，扩建后成为廊，晒太阳吹风处，墙头仙人掌 + 猫群 + 葡萄藤 + 菜地都在此处

猫群设计：慵懒墙头睡觉型（点了翻身）、警惕型（点了跑开再回头）、亲人型（点了朝小人走来两步）。

## 交互设计

- **点击语义**：命中物件→小人走近(1.5m)→动效+记忆卡；命中地面→走过去；天空→无反应
- **走路速度**：约 1.5m/s 闲庭信步，不设跑步
- **跟随相机**：第三人称平滑跟随，射线防穿墙（被建筑遮挡自动拉近）
- **开场小电影**：标题页「推门进院」→ 院门外小人背对镜头 → 门开小人自己走进去（脚本驱动）→ 镜头跟随穿过前院到廊亭站定 → 控制权交给玩家（自带教学）
- **记忆卡**：物件动效 ~400ms 后卡片底部滑入；老照片 + 标题 + 回忆文字；字号 ≥ 18pt 等效；关闭按钮大

## 氛围系统（永远在动的底噪）

炊烟般微风感、蝴蝶 2-3 只（绕月季/菜地）、葡萄藤漏光斑缓移、猫呼吸起伏、树影。不依赖点击，院子「活着」。

## 技术架构

```
Vite + React 18 + TypeScript
React Three Fiber + drei          # 3D 即组件
zustand                           # 全局状态（小人位置/当前记忆卡）
Tripo                             # 图生 3D 资产
gltf-transform                    # 模型压缩（draco/meshopt）
```

三块核心：

1. **场景**：前院/廊亭/后院三大块，光照（夏天午后暖光+树影）
2. **系统**：点击寻路（地面射线+圆形碰撞+转向，不上 NavMesh）、跟随相机、HotspotSystem（射线检测→动效→记忆卡）、AmbientLife（氛围动效）
3. **UI**：标题页、记忆卡、加载条（React DOM 层叠于画布上）

小人：Tripo 低多边形小孩 + Mixamo 免费「走/待机」动画重定向，不追求像任何人。

### 性能预算（移动优先硬约束）

| 指标 | 目标 | 手段 |
|---|---|---|
| 首次加载 | ≤ 15MB | 模型逐个压缩、照片 WebP 懒加载 |
| 帧率 | 中端手机 60fps | 植被 InstancedMesh、假阴影贴片、DPR 封顶 2 |
| Draw calls | < 80 | 合并静态网格、共享材质 |

降级：帧率持续 <30 → 自动降分辨率 + 关粒子。

### 资产生产线

```
老照片 ─→ Tripo 图生3D ─→ glTF ─→ gltf-transform 压缩（单模型 ≤1MB） ─→ assets/models/
```

- 每物件的建模提示词由 Claude 写，用户拿去喂 Tripo 并贴参考照片，导出后丢进项目
- **像不像由用户把关**（Claude 本会话无图像输入，无法替用户验收）
- 模型约 20 个（11 hotspot + 建筑本体 + 地面植被），分批生产

### 项目结构

```
xiaoyuan/
├── src/
│   ├── scene/        # R3F 场景：前院/廊亭/后院/光照
│   ├── systems/      # ClickToMove · FollowCamera · HotspotSystem · AmbientLife
│   ├── ui/           # 标题页 · 记忆卡 · 加载条
│   └── app/          # 入口与全局状态
├── content/          # ← 用户以后只动这里
│   ├── hotspots.json #   物件→照片/文字/机位映射
│   └── photos/       #   老照片 WebP
└── assets/models/    # Tripo 产出的 glTF
```

内容与代码分离：加物件/换照片/改文字只改 `content/`，不碰代码。

### 部署

- MVP：静态托管即可，**第二周起每阶段微信内真机测试**（不是最后才测）
- 正式送人前：国内对象存储 + 备案域名（GitHub Pages/Vercel 国内不稳）

## 验证

- 内容校验脚本：hotspots.json 引用的照片/模型存在、机位合法
- Playwright 冒烟：加载、点击热点、弹卡
- 每阶段真机：用户手机 + 微信内打开

## MVP 明确不做（防蔓延）

音频、收集成就、屋内场景、四季切换、多语言、后端/账号/统计。均留架构余地。

## 已知风险

1. 跟随相机贴墙拉近的观感需打磨（有成熟解法）
2. 小人穿植被边缘观感需真机验证
3. 微信内置浏览器兼容性必须尽早验证（第二周起）
4. 回忆文字必须用户本人写，AI 只整理润色（假回忆家人一眼能看出来）
